Probes and a central PC

Many machines, one rewind room

Any machine running rsRewind can be a probe. It keeps recording on its own, seals finished history into files, and you carry those files to your main PC. There they appear as extra lanes next to your own history.

Why files, not a live stream

Survives bad networks

A probe never waits on the link. If the network or the main PC is down, it keeps recording locally and the files pile up until you move them.

Safe to repeat

Copy the same file twice, in any order, after a crash: importing it again changes nothing. Every file carries a checksum, so a half-copied file is refused, never half-imported.

You choose the road

LAN share, WireGuard, a sync tool, a USB stick. rsRewind adds no network code of its own, so there is nothing new to expose.

Set it up

  1. On each probe: install rsRewind and run rsrewind start. It is the same recorder as always.
  2. Seal history. Run rsrewind export. It writes segment files to %LOCALAPPDATA%\rsRewind\outbox, covering only moments that have been quiet for five minutes. Run it by hand or on a schedule: 
    schtasks /create /tn "rsRewind export" /sc hourly /tr "\"%LOCALAPPDATA%\Programs\rsRewind\rsrewind.exe\" export"
  3. Move the files to the main PC however you like, for example robocopy "%LOCALAPPDATA%\rsRewind\outbox" \\main-pc\rsrewind-inbox. Copying a file again later is harmless.
  4. On the main PC: rsrewind import \\main-pc\rsrewind-inbox. Each probe gets its own store under sources\<id>; rsrewind sources lists them.
  5. Look. rsrewind ui shows every machine as its own lane, and search covers all of them.

What to know

SituationWhat happens
Probe is offline for daysIt keeps recording. Seal and move the files when you can; a long gap becomes several files.
The same file arrives twiceThe second import says "already imported" and changes nothing.
A file is damaged or cut shortRefused with a message. Nothing is imported.
A probe is reinstalled and loses its data folderIt shows up as a new machine. Nothing is merged or overwritten.
A backup is restored on a probeFiles that reuse an old sequence number with different content are refused.
You delete history on the main PCIt stays deleted, even if the same files are delivered again.
You delete history on a probeThat machine forgets it and removes matching unsent files. Copies already delivered stay on the main PC. rsrewind forget tells you how many moments had already been sealed.

Trust the folder. Files are checked for damage, not for who made them. Anyone who can write into the import folder can pose as a probe. Keep that folder and the sources folder as private as the history itself. Authenticating probes is planned.
